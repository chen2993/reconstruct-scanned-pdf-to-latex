# 协作、批次基线与不可逆操作

重建一本几百页的教材是长时程、多单元协作的工作。并行只有建立在对齐基线和收敛门上才可靠；否则会出现重复接口、样式漂移、互相覆盖和“已派发但产物缺失”。本文件规定批次纪律、任务清单、收敛门和不可逆操作保护。

## 0. 调度者与执行单元

用一个**调度者**（主执行者）管理大量执行单元，是本工作流的基本形态。调度者负责：

1. 冻结并发布基线（`.cls`、API、样式卡片、审计配置）；
2. 把正文切成连续批次，逐个派发，不做全量并发；
3. 给每个单元生成自带上下文的**任务包**；
4. 验收每批产出，通过后才派下一批；
5. 汇总样式缺口、更新集中文件和 Git，发布成品。

执行单元只做分配页面内的转写与自检，不碰集中文件，也不自行扩大范围。`scripts/orchestrate.py` 把上面第 2–4 步变成可执行命令：

```powershell
python -X utf8 scripts/orchestrate.py <project> plan --batch 10 --concurrency 1
python -X utf8 scripts/orchestrate.py <project> next     # 生成下一个批次的任务包
python -X utf8 scripts/orchestrate.py <project> verify b001-010
python -X utf8 scripts/orchestrate.py <project> status
```

- `plan` 按 `\bookinput{1}{N}` 的真实范围切批，默认每批连续 10 页；
- `next` 生成 `dispatch/<batch-id>.md`，内含样式摘要版本、文件白名单、逐页页面分型、跨页交接和停工反馈格式；在飞批次数达到 `--concurrency` 上限时**排队而不派发**（默认上限 1，`--force` 仅在确知可并行时越过）；
- `verify` 检查该批：文件存在、非占位骨架、来源页标记齐全，并跑该批的语义审计；未通过则标记 `in_progress`；
- 任务包里的跨页交接覆盖批末边界；若某页结束时仍有**未登记**为可跨页的所有者，任务包会显式告警，而不是把问题留给下一单元。

状态存于 `.reconstruct-scanned-pdf-to-latex/dispatch.json`，任务包存于同目录的 `dispatch/`。调度者是唯一的写入者。

可选地在 `.reconstruct-scanned-pdf-to-latex/page-types.json` 里维护逐页分型，键是最终页面标识（如 `pages-023`），值是简短的类型名（如 `章节首页`、`普通正文`、`图表或公式页`）。`next` 会把分型写进任务包，执行单元就不必靠猜；缺失的页面在任务包里标为“未分型”，不会阻塞派发。分型来自样式总结阶段的逐页视觉检查，不是从文件内容推断的。

## 1. 基线先行

在派出任何内容单元前必须先冻结对齐基线，否则返工成本远高于等待：

- `.cls` 公共接口、`docs/class-api.md`、样式卡片和 `semantic-audit.json` 已完成并通过代表页样式复核；
- 目录与 PDF 书签自动生成的接口已验证（`\bookmaketoc`、`\bookbookmarkmodule`）；
- 一条命令能编译出完整书校样，且代表页视觉比对达到人工确认门槛。

基线未确认前只允许做输入审计、拆页、方向修正、样式卡片和样式实现，不得开始批量逐页转写。样式或接口基线变更后，受影响批次必须先重新读取新版本，不能沿用旧摘要继续写。

## 2. 阶段顺序不可交叉

先完成全局架构（结构、版式、字体、环境、主题、可配置项、原书各前后置模块），再启动全量逐页细节对齐。两阶段交叉会让“全局样式”和“页面内容”互相打断，产生大量重复修改；用户分阶段下发任务时按阶段边界执行，不把两阶段合并推进。

## 3. 任务清单

每个单元的任务必须自带，缺项时先补齐再派：

1. 本批连续页面范围与源页标识（`pages-xxx` 或前后置模块名），以及允许修改的文件白名单；
2. 当前样式摘要版本号；
3. 该批实际会用到的样式卡片（不附无关卡片）；
4. 该批页面分型（章节首页、普通正文、图表/公式页、封底等）；
5. 停工反馈格式（缺样式、样式变体、无法表达的版式）；
6. 跨页交接信息（仅当批次边界落在开放的可跨页所有者内）：环境名、起始页面标识、样式卡片版本、当前嵌套层级。

单元只读本页独立 PNG 转写，并同时查看上一页与下一页判断跨页承接；不得读取联系页、拼接图或缩略图蒙太奇，不得用 OCR 或 PDF 文字层。单元只写分配文件，不碰 `.cls`、`main.tex`、审计配置、样式卡片和 Git。

## 4. 收敛门

- 一次只推进一个批次：转写 → 逐行内容复核 → 编译与版式复核 → 主执行者验收；验收通过后再派下一批。
- 不把全量页面同时派出去。并发数按运行环境实际支持的上限取，达到上限后排队；重复派发、超限派发和把未验收批次当作已完成都会制造返工。
- “已派发”不等于“已完成”。每次派发后核对：目标文件是否存在、数量是否与派发一致、内容是否通过语义审计、跨页交接是否连续；只核对存在性不核对质量同样会漏错。
- 出现新样式缺口时暂停该批，由主执行者回到样式阶段补齐 `.cls`、API、卡片和审计配置，再通知所有受影响单元重新读取。

## 5. 汇聚与交接

- 每个单元的产出先独立复核（内容 + 编译 + 版式），再合入主线；主执行者在合入时统一检查接口一致性和全局环境栈。
- 并行单元各自维护自己的复核记录，主执行者汇总到 `reviews/`；原始需求、差异清单、问题和结论只写在 `progress.md` 和 `reviews/`，不写进页面源码。
- 需要保留的原始需求、阶段性结论和未决问题按“任务 → 决策 → 证据 → 结论”记录，避免后续单元凭记忆重建上下文。

`progress.md` 的“可复现输入”栏位必须在对应阶段完成时**就地填上**，不能留成模板占位：源 PDF 标识与 SHA-256、输入审计状态、书内印刷规格、`MediaBox` 范围、资源类型、页面分型、舍去页规则、拆页策略、命名范围都要有实际值，阶段清单同时勾选。它是后续单元恢复上下文的入口，只有结论没有证据来源就无法回溯。

## 6. 不可逆操作保护

- 删除文件、丢弃页面、覆盖或还原大批源码前，先确认工作树干净并已提交可回退的检查点（`git status --short`、必要时先提交）。
- 不用 `git restore`、`git checkout -- .`、`git reset --hard`、`stash` 或历史重写处理并行单元的改动；需要回退时按文件精确定位并保留证据。
- 删除文件属于大范围不可逆操作，先列出待删清单、确认都在项目目录内、且已有检查点，再执行；批量删除后立即验证关键源码仍在。
- 需要从历史或对话记录恢复内容时，先说明恢复范围与来源并保留原始字节；恢复后再与当前产物比对，不把恢复当作最终内容。
- 只有主执行者在验收后提交；并行单元不操作暂存区、提交、标签和历史。

## 7. 上下文预算：小批量、结构化优先

逐页转写天然要打开大量页面图，很容易一次塞入过多图片而超出上下文。把“看什么”的成本降下来，是这类工程能否跑到最后的关键：

- **先总览、再定位、后精读**。用 `scripts/crop_page.py --overview` 出一张缩略总览判断版面，再只截需要细看的那一块。**宽度决定清晰度**：横带（`--band`）只切高度，仍是整幅宽度，不会让公式变清楚；看清公式要用 `--region` 把宽度截窄。
- **按需取块，块数越少越好**。一页通常 1–3 块就够；不要为了“看全”把整页均分成十几条逐条读完。
- **一次只看少量页面图**：默认 1–2 张。用户说“不要一次看这么多照片”“避免过大图片”“降低上下文长度”时，立刻把批量降下来，不要找理由继续铺开。
- **不要靠放大补清晰度**：插值放大会同时放大模糊；页图源分辨率不足时回到拆页阶段用更高 DPI 重出。
- **先用结构化信号缩小范围，再打开图片**。多数问题不需要看图就能定位：页数漂移比较来源页标识与输出页码、目录与书签读 `.toc` 和 outline、盒警告与 `Overfull` 读日志、稀疏页用 `scripts/audit_page_density.py` 的墨迹统计。只在命中异常时才打开那一张页图。
- **不要为看图写一次性脚本**。裁剪、缩放、总览都由 `scripts/crop_page.py` 覆盖；每写一个只用一次的 `crop2.py`、`crop3.py`，都是在把上下文花在重复造工具上。
- **报告差异时只报有证据的局部原因**，不要整章、整本地铺开。
- 长任务要留下**可续的交接摘要**：当前目标、已完成、关键量测（页数、纸张、章节锚点）、待办和已知阻塞。后续单元靠这些文件恢复状态，不依赖对话记忆。

这不是省事的借口，而是让长篇工程收敛的工作方式：先用很少的上下文把问题缩小到几页，再用上下文去真正看清那几页。
