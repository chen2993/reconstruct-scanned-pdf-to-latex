# 读页面的方式

每个转写单元每次开工都要用到这份规则，所以它单独成篇。核心只有一句：

> **宽度决定清晰度。** 图片读取会按长边等比例缩小；把页面切成更短的横带不会让公式变清楚（横带仍是整幅宽度，照样被缩小），只有把宽度截窄才看得清。

其余规则都是这一条的推论。

## 工具：`scripts/crop_page.py`

```powershell
# 总览：定位版面分区、栏数、图形位置。不要用它读公式。不占读图预算。
python -X utf8 scripts/crop_page.py <project> pages-013 tmp/over.png --overview

# 横带：保留整行版式，顺序读一页的内容
python -X utf8 scripts/crop_page.py <project> pages-013 tmp/p013_b1.png --region 0.03,0.03,0.96,0.28

# 区域：只截公式、表格或图所在的一块，比例基于整页、原点左上
python -X utf8 scripts/crop_page.py <project> pages-013 tmp/p013_z.png --region 0.08,0.30,0.55,0.45
```

每次调用都会报告输出尺寸、源 dpi 与等效 dpi。提示"会被缩小"时说明这一块仍太宽，要再截窄。

## 操作纪律

- **先总览、再定位、后精读**：总览确定"哪一段有公式/表格/图"，随后只截那一块。不要把整页均分成十几条逐条读完——那是把上下文花在空白和已读内容上。
- **按需取块，越少越好**：一页通常 1–3 块就够。正文段落用 `body` 级清晰度即可，只有公式、角标、表格线、图形标注需要更高清晰度。
- **左右留 0.03 / 0.96**：正文常排到版心边沿，把 x 范围收到 0.09 会切掉行首字（实测「与」「所以」「该」「令」被切走），只能重裁、白烧额度。
- **不靠放大补清晰度**：`--scale` 大于 1 只是插值放大，会同时放大模糊，占更多上下文却不增加信息。看不清只能靠**收窄宽度**；源分辨率不足时回到拆页阶段用更高 DPI 重出。
- **裁图只写 `tmp/`**：脚本会拒绝写入交付树。裁图是临时视觉证据，用完即弃。
- **绝不拼图**：不得生成联系页、缩略图墙、多页拼接图；一次只处理一页，输出也只对应一页。

## 读图预算：硬上限，由脚本强制

**每页默认 6 次**（`--overview` 总览不计入）。**裁剪即计数**——`crop_page.py` 在产出裁图后自动登记，额度用尽时**直接拒绝裁剪**并提示停下报告。

这不是纪律口号，而是实测教训：有单元为了"更仔细"把一页裁成 20 多张逐张读，上下文烧光、任务中途崩溃，前面读的全白费。

- 超预算 = **任务失败**，不是"更仔细"。停下并用 `BLOCKED` 报告卡在哪一块。
- 确实需要更多额度时，由**调度者**显式提高上限并在进度记录里说明原因；单元不得自行放宽。
- 查余额与整批状态：

```powershell
python -X utf8 scripts/read_budget.py <project> check pages-013
python -X utf8 scripts/read_budget.py <project> report
```

## 防止"图读错了"被当成"原书错了"

并行读图与共用文件名会造成**图文错配**：拿到的可能是别页的图。这会诱导出完全错误的结论——实测有单元因此误判"全书页码偏移了 6 页"。

- 裁图文件名**必须带页号前缀**（`tmp/crops/p013_b1.png`）。多个单元共用 `tmp/`，无前缀的公共名会被并发单元覆盖：实测两张本应不同的裁图**逐字节相同**，单元看到的是别页的页眉。
- **不要在同一条消息里并行读多张图**，一次 1–2 张，读完再读下一张。
- 拿到图先核对**可自证的锚点**（页眉、印刷页码、章节标题）与本页标识是否一致。
- 不一致时先怀疑错配：单张重读 + **换一个新文件名**重裁，不要先宣布"原书页码偏移"或去改编号。
- 只有在换名重裁后**仍然**不一致，才按"原件与预期不符"报告，并附重裁文件名与看到的页眉文字。

## 视觉能力自检

单元开工前先裁一张图**亲自读**，确认这条路径有视觉能力。若返回"不支持视觉"之类的占位文本，立刻停下报告：

- **不要派下二级代理代读**：实测下级可能被固定在无视觉路径上，同样读不到图；
- 图片必须由单元**亲自裁、亲自读**；
- 也不要改用 OCR 或 PDF 文字层作为替代——源扫描件本就没有文字层，这类"替代"只会引入臆造。
