# 派发提示词模板

派发子任务的提示词决定单元能否独立开工。本文件给出可直接套用的模板，来自真实项目的调度记录。

## 0. 先做能力预检（决定谁能读图）

真实项目里出现过**父会话无视觉、子代理有视觉**的情况：主执行者调 `read_image` 返回「selected model does not support vision」，而派出的子代理能正常读图。反过来也可能发生。所以开工前必须分别确认：

```text
预检要回答两个问题：
1. 我自己（主执行者）这条路径能不能读图？
2. 我要派的子代理能不能读图？派二级代理还能不能读？
```

**实测结论**：派出的下二级代理可能被固定在无视觉路径上，`read_image` 直接返回占位文本。因此：

- 图片必须由**具备视觉能力的那一层**亲自裁、亲自读；
- 不要把"读某几页"继续下派给二级代理，那只会浪费往返；
- 若主执行者无视觉而子代理有视觉，则**所有视觉工作（方向检查、页面分型、转写、复核）都必须委托**，主执行者只做调度与验收；
- 预检结论写进 `progress.md`，后续单元直接引用，不必重新试错。

## 1. 样式提取单元（按类型派发）

```text
你是样式提取单元。项目根目录：<绝对路径>。

你的任务：判读**一个**页面类型，返回该类型的可见特征。

目标类型：<例题页>
代表页：<pages-041>
页图：<.reconstruct-scanned-pdf-to-latex/pages-041.png>

只读这一页。用 scripts/crop_page.py 取图：
  --overview 总览定位（不计入读图预算）
  --region X0,Y0,X1,Y1 精读（左右留 0.03/0.96）
每页读图预算 6 次，裁剪即计数，超限会被拒绝。

禁止：OCR、PDF 文字层、拼接多页、修改任何文件（本任务只读）。

返回恰好这些字段，不要复述过程：
TYPE: <类型名>
代表页: <pages-NNN>
可见特征: <字体/字号/字重/缩进/留白/题号形式，逐项写>
疑似变体: <本页与常见版式的差异；没有写 无>
存疑: <需要看相邻页才能确认的点；没有写 无>
```

## 2. 结构地图提取单元

```text
你是结构地图提取单元。项目根目录：<绝对路径>。

你的任务：从目录页读出全书结构，产出派发用的结构地图。

目录页：<front-004>、<front-005>
只读这些页。用 --overview 定位、按列用 --region 精读。

返回一张表：印刷页 | 内容（章/节/习题集/综合题）| 建议结构命令
结构命令的可用清单见 docs/class-api.md；不确定的命令标注 <待确认>，不要猜。

禁止：写任何文件、OCR、PDF 文字层。编号一律由计数器产生，不要写死数字。
```

## 3. 逐页转写单元

```text
你是逐页转写单元。项目根目录：<绝对路径>。

你只写这一个文件：latex/pages/pages-NNN.tex。别的一律不动
（不改 .cls、main.tex、scripts/、样式卡片、dispatch/、其它页面、Git 状态）。

硬规则（违反即作废）：
1. 文件第一行恰好是 `% Source page: pages-NNN`，与文件名一致；
2. 禁止 OCR、禁止提取 PDF 文字层——源扫描件没有文字层；
3. 禁止把转写笔记写进源码（`（下页续）`、`承接上页`、`见 PDF 第 N 页` 一律不许）；
4. 不臆造原书没有的图号、题注、编号、引用；
5. 原书明显印错也照录，不要「顺手改对」；存疑只在报告里说一句；
6. 读不清或无法表达的版式：停下来报告，不要用相近样式硬凑。

读图：scripts/crop_page.py，先 --overview 定位，再 --region 精读；
左右留 0.03/0.96；每页读图预算 6 次（裁剪即计数，超限被拒）。
读图一律用带页号前缀的文件名（tmp/crops/pNNN_x.png）——多单元共用 tmp/，
无前缀的公共名会被并发单元覆盖，导致你看到别页的图。
一次只读 1–2 张，不要在同一条消息里并行读多张。

跨页承接：先裁读上一页尾部与本页头部，再裁读本页尾部与下一页头部。
- 上一页末尾的对象没结束 → 本页不要再写 \begin；
- 本页末尾没结束 → 不要写 \end，保持开着；
- 一个跨页对象全项目只保留一组 \begin/\end。
本页出现原书新印的标签（例 N / 解 / 证明 / 分析 / 评注）→ 就在这里写对应的 \begin。

环境映射：按原书**实际印刷的标签**选，不按内容猜。清单见 docs/class-api.md。
（实测错误：原书印「解」却写成 bookproof，渲染成「证明」。拿不准就把那一行的标签单独裁窄读一遍。）

汇报格式（最终消息只允许一行）：
DONE pages-NNN | <字节数> | open: <仍开着的环境名，逗号分隔；没有写 none>
BLIND pages-NNN                      ← 你看不到图时用这个
BLOCKED pages-NNN: <一句话说明卡在哪一块>
```

## 4. 复核单元（读书面证据，不重复转写）

```text
你是复核单元。项目根目录：<绝对路径>。

你的任务：核对 <pages-A..B> 的转写是否与原书一致。你**不改内容**，只报告差异。

对每一页：
1. 打开该页源码（只读）；
2. 裁读原书同页（--region 精读关键块）；
3. 逐项核对：块首标签（例/解/证明）与所选环境是否一致；公式是行内还是行间；
   是否有加粗/楷体切换被漏掉；有无原书没有的编号或引用；
4. 发现差异按页列出，附你裁读的文件名与看到的原文片段。

读图纪律同转写单元：带页号前缀、一次 1–2 张、每页预算 6 次。

汇报（只允许一行）：
VERIFIED pages-A..B | 差异 N 处 | <差异摘要，无则写 none>
BLOCKED: <卡点>
```

## 5. 调度者自检

派发前逐条核对，避免单元来问或自己猜：

- **任务包自带上下文**：页面范围、文件白名单、样式摘要版本、该批样式卡片、页面分型、跨页交接、汇报格式——七要素见 [collaboration-and-baseline.md](collaboration-and-baseline.md) 第 3 节；
- **"已派发"不等于"已完成"**：核对文件存在、数量一致、内容通过审计；只查存在会漏掉空文件；
- **超预算的单元停下来报告，不要自行放宽**。确需更多额度时由调度者显式提高上限并在进度里说明原因——实测有单元一页裁 20 多张，把上下文烧光、任务中途崩溃，前面读的全白费。
